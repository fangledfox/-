# 二经知识库 — 功能清单 & 给 Gemini 的提示词库

> 用法：先在「功能清单」里挑你要做的事，然后到「提示词模板」里复制对应的那段贴给 Gemini。
> 每次贴提示词时，记得把 `D:\二经知识库\` 整个目录作为附件上传。

## 一、可添加功能清单（按优先级）

### P0 — 让现有骨架真正好用（建议先做）

| # | 功能 | 价值 | 工作量 |
|---|---|---|---|
| 1 | **字段全局检索** | 按字段名或中文注释反查归属表——开发写 SQL 时最常用 | 小 |
| 2 | **批量粘贴优化** | 一次支持粘几百张表 DDL，解析完显示成功/失败明细 | 小 |

### 模板 1：加字段全局搜索

```

改完跑 python tools/build_portal.py 验证。

### 模板 2：写 parse_proc.py

```
在二经知识库项目里新增 tools/parse_proc.py：

职责：
- 扫描 scan/_sources/procs/ 目录下所有 .sql 文件
- 每个文件是一个 PL/pgSQL 存储过程
- 用正则抽：过程名（CREATE [OR REPLACE] FUNCTION/PROCEDURE 后面的名字）、输入参数、功能描述（前 200 行注释）
- 抽这个过程读写了哪些表（INSERT INTO / UPDATE / DELETE FROM / FROM / JOIN 后面的表名，schema 前缀可选）
- 结果写入 scan/procs.json，结构：
  {procs: {"p_xxx": {name, file, args, desc, read_tables: [], write_tables: []}}, total: N}
- 支持命令行：python parse_proc.py [file.sql] 单文件解析，不传参数扫整个目录
- 写之前先快照到 scan/_snapshots/

约束：只允许 Python 标准库（re/json/pathlib）。
注意分区子表归并：xxx_1_prt_p20260831 → xxx（用正则 _1_prt_p\d+$ 去掉）。
改完把 /api/procs 接口改成能读 read_tables/write_tables 字段，并在前端过程详情抽屉里展示。
```

### 模板 3：写血缘解析 + 可视化

```
在二经知识库项目里新增 tools/parse_lineage.py 并加血缘视图：

1. parse_lineage.py：
   - 扫描所有已入库的过程（scan/procs.json）和 _sources/sql/ 下的 SQL 文件
   - 匹配三类模式：
     a) INSERT INTO target SELECT ... FROM src1, src2
     b) CREATE TABLE target AS SELECT ...
     c) CREATE [OR REPLACE] VIEW target AS SELECT ...
   - 抽边：target → src（目标表依赖来源表）
   - JOIN 条件里的字段对也抽出来（ON a.x = b.y），存到边上
   - 分区子表归并父表
   - 结果写 scan/lineage.json: {edges: [{target, source, join_keys: ["a.x=b.y"]}], total: N}

2. 后端 /api/lineage?table=xxx：
   - 返回某张表的上游（它读了谁）和下游（谁读了它），各最多 3 层

3. 前端：
   - 表详情抽屉底部加「血缘」区
   - 上游：缩进列表显示，每行 [schema 徽章] 表名（join_keys 小灰字）
   - 下游：同样缩进列表
   - 没有血缘显示「暂无血缘数据」

纯离线，不用 mermaid/D3。缩进列表够用。
```

## 三、怎么组合

- **第一次给 Gemini 派活**：先贴主提示词（`给Gemini的提示词.md`），再贴上面任一模板
- **多轮迭代**：每次只贴一个模板，不要一次塞 5 个功能
- **改 UI 时**：把模板里"保持现有 UI 风格（深色顶栏、indigo 主色、暗色模式）"那句留着
- **改后端时**：提醒它"改完跑 python tools/build_portal.py，并确认 /api/* 接口返回正常"
